# Challenge Notes

The project intentionally contains TODOs and incomplete behavior.

The supplied runner is an acceptance-style executable. It should initially report failures and should report PASS only after the candidate implements the required behavior.

The runner uses deterministic board setup for movement and merge scenarios. It validates board values, game state, score, and tile count.

The candidate may add/refactor classes and methods when this improves the design, while preserving the required behavior.
